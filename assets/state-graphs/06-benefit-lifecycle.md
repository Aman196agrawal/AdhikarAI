# 6. Benefit lifecycle state machine

Every graph moves a benefit through these states. The source of truth is
`TRANSITIONS` in `lib/engine/stateMachine.ts`; any transition not listed there
throws `Illegal lifecycle transition`.

## Main path (simplified)

Obtain → get paid → verify receipt, with the recovery loop on the right.
Approval gates are the two `AWAITING_*` states.

```mermaid
stateDiagram-v2
  direction TB
  [*] --> DISCOVERED
  DISCOVERED --> ELIGIBLE
  DISCOVERED --> POTENTIAL_ENTITLEMENT
  POTENTIAL_ENTITLEMENT --> ELIGIBLE
  ELIGIBLE --> APPLICATION_DRAFT
  APPLICATION_DRAFT --> AWAITING_APPLICATION_APPROVAL
  AWAITING_APPLICATION_APPROVAL --> SUBMITTED: gate 1 approved
  AWAITING_APPLICATION_APPROVAL --> APPLICATION_DRAFT: gate 1 rejected
  SUBMITTED --> PENDING
  PENDING --> APPROVED
  PENDING --> REJECTED
  APPROVED --> DISBURSED
  DISBURSED --> RECEIPT_UNVERIFIED
  RECEIPT_UNVERIFIED --> CITIZEN_CONFIRMED
  CITIZEN_CONFIRMED --> VERIFIED_RECEIVED
  DISBURSED --> PAYMENT_DISCREPANCY
  VERIFIED_RECEIVED --> MONITORING

  REJECTED --> GAP_DETECTED
  PAYMENT_DISCREPANCY --> GAP_DETECTED
  MONITORING --> GAP_DETECTED: missed payment

  state "Recovery loop" as recovery {
    GAP_DETECTED --> ROOT_CAUSE_IDENTIFIED
    ROOT_CAUSE_IDENTIFIED --> ACTION_PLANNED
    ACTION_PLANNED --> AWAITING_ACTION_APPROVAL
    AWAITING_ACTION_APPROVAL --> ACTION_EXECUTED: gate 2 approved
    AWAITING_ACTION_APPROVAL --> ACTION_PLANNED: gate 2 rejected
    ACTION_EXECUTED --> REVERIFYING
    REVERIFYING --> RECOVERED
    REVERIFYING --> RE_AUDIT_REQUIRED: not recovered
    RE_AUDIT_REQUIRED --> GAP_DETECTED
  }

  RECOVERED --> MONITORING
  MONITORING --> RE_AUDIT_REQUIRED: scheduled tick
```
